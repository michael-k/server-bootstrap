# NFTables Firewall Configuration
# Generated by Ansible - DO NOT EDIT MANUALLY
#
# This configuration implements a dual-stack (IPv4 + IPv6) stateful firewall
# with default-deny policies and explicit allow rules.
#
# Requirements: 8.1, 8.2, 8.3, 8.4, 8.5, 8.6, 8.7, 8.8, 8.9

# Flush existing rules
flush ruleset

# Define table for both IPv4 and IPv6 (inet family)
table inet filter {
{% if not (firewall_tailscale_enabled | bool) and (firewall_port_knocking_enabled | bool) %}
    # Port knocking sets — track knock sequence progress per source IP
    # Sets must be at table level (outside chains) per NFTables syntax
{% for af, addr_type in [('4', 'ipv4_addr'), ('6', 'ipv6_addr')] %}
    set knock{{ af }}_stage1 { type {{ addr_type }}; flags timeout; timeout {{ firewall_port_knocking_stage_timeout }}s; }
    set knock{{ af }}_stage2 { type {{ addr_type }}; flags timeout; timeout {{ firewall_port_knocking_stage_timeout }}s; }
    set knock{{ af }}_passed { type {{ addr_type }}; flags timeout; timeout {{ firewall_port_knocking_timeout }}s; }
{% endfor %}

{% endif %}
    # Input chain - handles incoming traffic
    # Default policy: drop (Requirement 8.5)
    chain input {
        type filter hook input priority 0; policy drop;

        # Allow established and related connections (Requirement 8.3)
        # This enables stateful firewall behavior
        ct state established,related accept

        # Allow loopback interface traffic (Requirement 8.4)
        # Required for local services to communicate
        iif lo accept

        # Allow ICMPv4 and ICMPv6 for network diagnostics
        # Ping, path MTU discovery, etc.
        ip protocol icmp accept
        ip6 nexthdr icmpv6 accept

{% if firewall_tailscale_enabled | bool %}
        # Tailscale VPN is enabled - restrict SSH to Tailscale interface only
        # (Requirements 8.7, 8.9)

        # Allow SSH only from Tailscale interface
        iifname "{{ firewall_tailscale_interface }}" tcp dport {{ firewall_ssh_port }} accept

        # Allow Tailscale WireGuard traffic (UDP port {{ firewall_wireguard_port }})
        # Required for Tailscale VPN to function
        udp dport {{ firewall_wireguard_port }} accept
{% elif firewall_port_knocking_enabled | bool %}
        # Port knocking is enabled - SSH only after correct knock sequence
        # Knock sequence: {{ firewall_port_knocking_sequence | join(' -> ') }}
{% for af, saddr in [('4', 'ip saddr'), ('6', 'ip6 saddr')] %}

        # IPv{{ af }} knock sequence
        tcp dport {{ firewall_port_knocking_sequence[0] }} add @knock{{ af }}_stage1 { {{ saddr }} }
        tcp dport {{ firewall_port_knocking_sequence[1] }} {{ saddr }} @knock{{ af }}_stage1 add @knock{{ af }}_stage2 { {{ saddr }} }
        tcp dport {{ firewall_port_knocking_sequence[2] }} {{ saddr }} @knock{{ af }}_stage2 add @knock{{ af }}_passed { {{ saddr }} }
{% endfor %}

        # Drop knock port packets after set processing
        tcp dport { {{ firewall_port_knocking_sequence | join(', ') }} } drop

        # SSH access (only for IPs that completed knock sequence)
        tcp dport {{ firewall_ssh_port }} ip saddr @knock4_passed accept
        tcp dport {{ firewall_ssh_port }} ip6 saddr @knock6_passed accept
{% else %}
        # Tailscale VPN is disabled, port knocking is disabled
        # Allow SSH from all interfaces (Requirement 8.8)
        tcp dport {{ firewall_ssh_port }} accept
{% endif %}

        # Log dropped packets (optional, for debugging)
        # Uncomment to enable logging:
        # log prefix "nftables-drop: " drop
    }

    # Forward chain - handles forwarded traffic
    # Default policy: drop (Requirement 8.6)
    chain forward {
        type filter hook forward priority 0; policy drop;

        # No forwarding rules needed for this configuration
        # All forwarding is blocked by default
    }

    # Output chain - handles outgoing traffic
    # Default policy: accept (allow all outbound traffic)
    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

# Port Knocking

Port knocking hides the SSH port from network scanners. Instead of leaving SSH open to the internet, the firewall requires you to send a specific sequence of TCP packets to predetermined ports before it opens SSH for your IP address.

## When Is Port Knocking Active?

Port knocking is active when:
- Tailscale VPN is **disabled** (or not configured)
- `port_knocking_enabled` is **true** (the default)

When Tailscale is enabled, SSH is already hidden behind the VPN and port knocking is not needed.

## Default Knock Sequence

The default sequence is: **7000 → 8500 → 9100**

After a successful knock, SSH opens for your IP for **30 seconds**. Once your SSH connection is established, it stays alive regardless of the knock timeout — you do not need to re-knock for an existing session.

## How to Knock

### Option 1: `knock` client (recommended)

Install the knock client:

```bash
# Debian/Ubuntu
sudo apt install knockd

# macOS
brew install knock

# Fedora
sudo dnf install knock
```

Knock and connect:

```bash
knock <host> 7000 8500 9100 && ssh user@<host>
```

### Option 2: Bash (no client needed)

Using bash built-in `/dev/tcp`:

```bash
for p in 7000 8500 9100; do
  echo >/dev/tcp/<host>/$p 2>/dev/null
  sleep 0.1
done
ssh user@<host>
```

### Option 3: Netcat

```bash
for p in 7000 8500 9100; do
  nc -z -w1 <host> $p 2>/dev/null
  sleep 0.1
done
ssh user@<host>
```

## Customizing the Sequence

Edit your inventory variables:

```yaml
port_knocking_sequence:
  - 4321
  - 8765
  - 2468
```

The sequence must contain exactly 3 ports.

You can also adjust timeouts:

```yaml
port_knocking_timeout: 30        # seconds SSH stays open after knock
port_knocking_stage_timeout: 5   # seconds between knocks before reset
```

## Disabling Port Knocking

To allow SSH without knocking (not recommended for public-facing servers):

```yaml
port_knocking_enabled: false
```

## Troubleshooting

### Check if knock sets exist

```bash
sudo nft list sets
```

### Check if your IP passed the knock

```bash
sudo nft list set inet filter knock4_passed
sudo nft list set inet filter knock6_passed
```

If your IP appears in the set, SSH should be accessible.

### Common issues

- **Knock timeout**: You have 5 seconds between each knock port. If you're too slow, the sequence resets. Increase `port_knocking_stage_timeout` if needed.
- **Wrong port order**: The sequence must be sent in the exact order configured.
- **Firewall blocking knock ports**: Intermediate firewalls or NAT devices may block the knock packets. Use TCP (the default) which works through most firewalls.
- **IPv6 vs IPv4**: The knock sequence works identically over both protocols. Make sure you're connecting over the same protocol you knocked on.
```
